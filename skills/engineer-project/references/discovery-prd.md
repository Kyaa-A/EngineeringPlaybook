# Discovery, PRD, and Scope

## Outcome

Define the user, problem, evidence, constraints, and measurable result before choosing technology.

## Discovery

Answer:

- Who has the problem and how do they solve it today?
- How frequent, painful, and valuable is it?
- What evidence is known versus assumed?
- What is the smallest valuable end-to-end workflow?
- What must never happen?
- Which legal, privacy, budget, time, and platform constraints apply?

## PRD

Use `templates/PRD.md`. Include the problem, target users, goals, metrics, workflows, requirements, acceptance criteria, non-goals, risks, and MVP boundary. Requirements describe outcomes; architecture belongs in the TDD.

## Exit gate

- [ ] Target user and problem are specific.
- [ ] Evidence and assumptions are separated.
- [ ] Success has a baseline and target.
- [ ] MVP contains one coherent user journey.
- [ ] Acceptance criteria are observable.
- [ ] Non-goals prevent scope expansion.
- [ ] Risks and unknowns have owners.
- [ ] The PRD is approved.
